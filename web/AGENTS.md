## What this app is

A local-first *view* over the same files the CLI reads and writes. There is no
database, no server, no parallel engine: the tracker on screen is
`data/applications.md` parsed at request time. A change that makes the web the
source of truth for anything is a change to the architecture, not a feature.

Stack: Next 16 (App Router, Turbopack), React 19, Tailwind 4, TypeScript. See
[`README.md`](README.md) for setup; the app is alpha and opt-in.

## Where the user's files live

`careerOpsRoot()` in `src/lib/career-ops.ts` resolves the checkout: `..` in
production (the app ships inside the checkout), overridable with
`CAREER_OPS_ROOT` in `web/.env.local` for development against sample data.
Never join paths from `process.cwd()` directly — that silently resolves to
`web/` and reads a file that is not the user's.

Call a core script through `rootScript("doctor")`, which assembles the `.mjs`
suffix at runtime. This is not stylistic: Next's bundler statically traces a
literal `"doctor.mjs"` passed to `execFile`/`spawn` as a module import and fails
the production build.

## Writes

**Every user-layer write goes through `src/lib/core/safe-write.ts`.** It writes a
uniquely-named temp file in the same directory and renames it, so a kill
mid-write cannot truncate the real file, and `atomicWriteWithBackup` snapshots
the prior contents to `{file}.bak-{timestamp}` first. User files are gitignored,
so that backup is the only recovery path — data loss here is unrecoverable, not
inconvenient (`#649`, `#704`, `#920`, `#958`).

Status changes and tracker rows go through the core's own scripts
(`set-status.mjs`, `merge-tracker.mjs`), never a hand-rolled table edit in this
app. Two writers with different ideas about the format is the failure mode.

## Agent workers

`/api/run` dispatches CLI workers, and the tool scope is decided in
`src/lib/claude-invocation.mjs`, not at the call site:

- `PERSISTING_KINDS` (`evaluate`, `fix-portal`) run the real mode and need
  `Write` + `Bash` to produce canonical artifacts.
- Everything else gets the read-only scope, **including any kind nobody has
  reviewed yet** — an unknown kind resolving to write access is the one
  unrecoverable default.
- `pdf` is read-only on purpose: it emits the tailored CV inline in a
  `<<cv-html>>` envelope and the backend parses and writes it. Job postings and
  reports are untrusted input reaching that agent, so it holds no write tool at
  all (`#2185`). Do not "fix" a pdf worker by granting it `Write`.

Note the honest limit, and keep it honest: the disallowed-tools guarantee is
Claude Code-specific. Other CLIs are invoked with a bare prompt and keep their
default tool access — what holds everywhere is that the rendered CV is the one
the backend parsed out of the envelope.

## Core mirrors

`src/lib/core/normalize-text-key.mjs` is a mirror of the core's
`tracker-parse.mjs` key normalization, kept so a partial checkout still works.
Mirrors drift silently by nature, so the root suite freezes parity against a
corpus with expectations *derived* from the core, never hand-written (`#2666`,
`#2700`). Change one side and you must change the other.

## Tests

```bash
npm test             # node --test over tests/**, plus the two root-level test-*.mjs
npx tsc --noEmit     # typecheck
npm run build        # production build — catches the bundler traps above
```

`web-ci.yml` is informative-only. The **required** gate is the root
`test-all.mjs`, which discovers and runs every `web/tests/lib/*.test.mjs` rather
than a hand-written list — so a new suite dropped in that directory gates
automatically, and a suite deleted from it stops gating just as quietly.
